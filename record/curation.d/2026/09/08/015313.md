**The lint caught something the new workflow made possible.** With views no
longer generated on branches, two clusters can be worked in parallel off
`main` instead of stacked — and the first time that happened, one practice
cited `SOTA-tmp54nas`, a temporary code that exists only on the *other*
branch.

`luria lint` reported it as an unresolved code, which is exactly right and
worth writing down as a rule rather than an incident:

> **A merge-allocated temporary code is branch-local by construction.** It is
> a placeholder for a number that will be assigned when the branch merges,
> and two branches in flight have no way to know each other's assignments —
> so a cross-branch reference is not merely unresolvable now, it would resolve
> to the *wrong* document later if it resolved at all.

The fix is to cite the **note** instead. `LIT-166` is a real code on `main`;
the practice drawn from it is not yet. Referring to "the four-epoch practice
drawn from [LIT-166](../../record/literature.d/LIT-166.md)" says the same thing, resolves today, and stays true after
both branches land under whatever numbers they get.

That generalises: **across branches, refer to the stable thing.** Literature
codes are stable because notes are filed before the practices that cite them;
practice codes filed in the same contribution are not.

## The trade the new workflow bought, stated plainly

Before, parallel branches conflicted on generated views, so the natural move
was to stack — and stacking made every merge a re-resolution. Now branches
are independent and the only thing they can collide on is a temporary code,
which the lint catches at the citing site rather than at merge time.

That is a better failure: it is local, it names the file and the code, and it
is fixed by writing a sentence differently rather than by re-running a
generator and re-staging nineteen files.

## The cluster

Two practices — filter by token horizon, and build synthetic data by editing
human text — and two notes that now say why they keep none. Those two
refusals are worth having beside each other, because the reasons are
different and both are reusable:

- **[LIT-184](../../record/literature.d/LIT-184.md), FineWeb: scope.** A dataset is not a technique. Its
  transferable content is an ablation methodology, and it lands in the
  filtering practice as the position that practice argues against.
- **[LIT-125](../../record/literature.d/LIT-125.md), Qwen2.5-Coder: [ADR-017](../../record/decisions.d/ADR-017.md).** A model report describes a recipe in
  full and isolates none of it. It supplies adoption, not evidence about a
  claim.

Neither is "nobody at frontier scale does it", which is the reason the whole
sweep exists to stop giving.
