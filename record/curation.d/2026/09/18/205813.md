The unbound-lineage report is empty for the first time. Twenty-two relations
and ten lines down to zero, by naming what twenty-one documents were already
about.

## Three passes, and the first two argued with the instrument

`ADR-036` classified twenty-four unbound relations and left twenty-two,
concluding that the ones involving `analysis-and-evaluation` showed the
invariant was over-strong. `ADR-048` — mine, this morning — re-examined them,
bound six, and repeated the conclusion for the rest. Then I went further and
proposed an `unbound-ok:` directive to luria so the recurring ones could be
marked deliberate.

Each step was reasoned, and each made the same move: treat a finding that
keeps recurring as evidence about the **checker**.

It is almost always evidence about the **input**. A relation is an assertion
that two documents have something in common; the author wrote it because they
could see the commonality. So the commonality exists, and if no tag names it,
the tag is missing. There is no reading under which the right answer is to
record that somebody looked and moved on.

`invariants.py` says this in its own docstring, and all three passes read past
it:

> Its usual reading is not that the documents are mis-related but that **the
> vocabulary is missing a word**.

## The measurement that settled it

`analysis-and-evaluation` looked like the culprit because it names a kind of
work where the other twelve name subjects. The obvious fix — drop it — dies on
one count:

| documents carrying it | |
|---|---|
| **91** | total |
| **74** | where it is the only tag |
| **64** | solo **and declaring no relations** — benchmark notes, where evaluation *is* the subject |
| **8** | solo **and in a chain** |

Those 8 were the entire problem. The tag is fine; it was standing in for a
subject in eight places. And the split is the report's own doing — it flags
documents in chains and ignores the 64 identical-looking ones that are not,
because a relation is the evidence that something is missing. The instrument
had already separated the two cases correctly.

## The fossil

Chasing this turned up a `groups.primary_topic` block listing thirteen of the
fourteen topics, which I first read as a deliberate statement that
`tiny-models` is not a primary topic. It is not deliberate and it is not a
statement. `require: any` is luria's default and means *"the group is a label,
not an axis"* — it constrains nothing. The block's own comment still says
*"the topic consolidation, enforced… exactly one primary per practice"*,
which was true until `ADR-035` relaxed it from `exactly-one`.

Then, being inert, it drifted: `tiny-models` joined the vocabulary and never
the list, and nobody noticed, because **nothing read it**. A rule that stops
being enforced does not announce itself; it just stops being true, quietly, at
whatever rate the thing it describes changes.

`DP-002` names the shape — a field every record shares is a comment with a
schema — and this was the degenerate case: a comment with a schema that had
also gone stale.

## What is left

Nothing, in this report, which is the point. Every future finding is new, and
there are two things it can mean. The next unbound relation says something is
wrong *today* rather than joining a standing backlog that a reader has to
re-derive from three decisions.

The question of whether the vocabulary wants **more kinds of work** is
deferred rather than answered. What makes deferring safe is the rule this
pass establishes: a kind-of-work tag never stands in for the subject of a
document that is about something. Add a kind when a document wants one, the
way `ADR-027` added this one.
