---
title: 'I cited a decision for the opposite of what it now implies'
created: '2026-09-22T21:07:53'
tags: [record, curation]
---

**The correction came from being asked, not from a check.** I wrote into
`luria.yaml` yesterday that a temporary code there would go stale because
concretization does not reach the config, and cited `ADR-039` for it. Asked
whether that was still true, I read `luria/concretize.py` instead of re-reading
the decision. `_rewrite_files` iterates `cfg.code_globs` and does a plain
string replace. `ADR-039` put `luria.yaml` in `code.globs`. So the answer is
no, and it has been no since the day `ADR-039` merged.

**The instructive part is *why* the decision reads the way I read it.**
`ADR-039`'s Context says "Nothing was rewriting the config, and nothing was
reporting that it had not been." That sentence is accurate — it describes the
state *before* the decision. The decision then added the glob, which turned on
the lint and, as a side effect nobody wrote down, turned on concretization
too. Its Consequences section lists what the lint now finds and says nothing
about repair. A document that describes a problem in the present tense and
then fixes it without amending the description will be read, later, as
describing the present. It was, by me, six days on.

So v3 is a Consequences note rather than a correction to the Context. The
history is right; what was missing is that the decision ended the history it
narrates.

**Then the probe turned up a second wrong belief, older and more load-bearing.**
Since 21 September the record has been repeating that concretization "does not
reach inside backticks". It does — a plain string replace over file contents
does not know what a backtick is. I wrote that sentence into three fragments
and two curation entries this week, and hand-fixed sixteen citations on the
strength of it.

What is actually true is narrower and belongs to a different command:
`luria link --fix` upgrades a **bare** already-concretized code and leaves
`` `ADR-tmpxxxxx` `` alone. It also leaves a hand-written
`[ADR-tmpxxxxx](ADR-tmpxxxxx.md)` alone, which nobody had noticed at all. Two
commands with different jobs got one shared folk explanation.

**And the real cause of the hand-fixing was `#211` the whole time.** Those
citations were codes another branch had already concretized. There was no
pending rename left for `luria concretize` to apply, so it did not matter what
they were wrapped in. The issue for that is open; this contribution is the
first time the record has evidence for it rather than a hypothesis.

**What I want to take from this.** Every other error I caught today was caught
by machinery — the lint, the hook, a report. This one could not have been: no
check reads English in a config comment for truth. It was caught because
somebody asked whether a claim I had asserted confidently was still true, and
because the only honest way to answer was to go and run it.

The cheap move was available the whole time and I did not take it: the luria
source is checked out at `/home/user/luria`, and the probe that settled both
questions took four minutes. I had been reasoning from a decision document
about a behaviour I could have measured. `DP-010` is usually about a paper's
most quotable sentence; this is the same failure applied to this record's own
prose.
