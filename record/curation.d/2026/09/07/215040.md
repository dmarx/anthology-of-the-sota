**The first batch of [#56](https://github.com/dmarx/anthology-of-the-sota/issues/56) was filed as four notes and zero practices, and that
was wrong.** The three papers with a recommendation in them are now
[SOTA-156](../../record/practices.d/SOTA-156.md), [SOTA-155](../../record/practices.d/SOTA-155.md) and [SOTA-154](../../record/practices.d/SOTA-154.md), all `Proposed`. Writing down
why the first pass went the other way is worth more than the correction,
because the mistake was not about these papers.

## The rule I applied, and why it is the wrong rule

The reasoning was: *a practice needs the thing to work, and somebody at the
relevant scale to be doing it.* All three papers fail the second half —
Schedule-Free's evidence tops out far below where [LIT-131](../../record/literature.d/LIT-131.md) and [LIT-145](../../record/literature.d/LIT-145.md)
disagree, DiLoCo is 8 workers on C4, ES is two tasks at 8B and below — so
none of them became a practice.

That sentence is a correct description of the bar for **`Active`**. It was
applied to the question of whether the document should **exist**, and those
are different questions. `statuses.yaml` says so in as many words:

> `Proposed` — *early results are good, validation at scale is missing — the
> old `experimental` flag*

That is a description of all three papers. The vocabulary already had the
slot; the filer used the top of the scale as the entry requirement.

## Why the error is not cosmetic

**A refusal has nowhere to put the thing that would reverse it.** Each of the
three notes ended with a sentence naming what would change the answer, in
prose, in a `LIT` document. [ADR-014](../../record/decisions.d/ADR-014.md) exists because that exact arrangement
failed before: a promotion condition living in prose is invisible when the
evidence arrives, and it was found last time only because somebody happened
to be re-reading two practices the same afternoon. Declining to file the
practice reproduces the failure [ADR-014](../../record/decisions.d/ADR-014.md) fixed, one layer up — the condition is
now not merely prose, it is prose attached to the wrong document.
`promote_when:` is a required field on a `Proposed` practice, and it was
sitting empty because no practice existed to require it.

**Consensus is a per-practice field, so a paper with no practice cannot
accumulate one.** [ADR-015](../../record/decisions.d/ADR-015.md) put `consensus:` on `SOTA` deliberately: it is a
claim about how far the field has moved on *a recommendation*. The second lab
to publish a Schedule-Free run has nowhere to be recorded if there is no node
to move from `unreplicated` to `emerging`. A refusal does not just withhold
an endorsement; it removes the counter that would have earned one.

**And it starves the status vocabulary.** [DP-2](../../docs/design-principles.md#dp-2) is that a field every record
shares is not a field. If only practices that already clear the `Active` bar
get filed, `Proposed` fills up with nothing but the cases somebody filed
optimistically and never revisited — which is precisely the distribution the
lint's `inert-status` check exists to catch, arrived at from the other
direction.

## What the notes were right about

The refusals were well-argued as *statements of what is missing*, and that
content survives intact — it moved into `promote_when:` and the "what is not
established" sections, where a machine can point at it. Two things also
stayed literature-only for a reason that holds up:

- The Veo 3 note reports emergent capability and recommends nothing. There is
  no instruction to file.
- The JEPA line is vision self-supervision, and `tags.yaml` gives `SOTA`
  seven primary topics, none of which is a vision category. The practice
  scheme is scoped to language-model training *by construction* — which is a
  much better reason than the one first given, and worth knowing about.

## The rule that replaces it

**File the practice whenever the paper contains an instruction; let `status:`
carry how much you believe it.** The question at filing time is "is there a
recommendation here", not "would I put my name on it today". A `Proposed`
practice with an honest `promote_when:` costs a paragraph and creates the
node that everything later attaches to. A refusal costs nothing now and costs
the node forever.

## Two mechanics of the acknowledgement directive, learned the slow way

Filing three `Proposed` practices meant three new inactive-citation findings
to acknowledge, and it took three lint cycles because the directive is
stricter than it looks:

- **It must name the code it vouches for.** `inactive-ok-block:` followed by
  a prose reason and no code acknowledges nothing — the finding stays, and
  the comment reads to a human as though it had been handled.
- **It must be contiguous with the block.** A blank line between the comment
  and the paragraph ends the block, so the directive covers only itself.
- And a corollary: a code written *inside* the comment is itself a citation
  at that line. Vouching for two codes takes two directives stacked, not one
  comment mentioning both — which is what the existing sites in this record
  already do, and now I know why.

One more, found by deleting the comment to see what happened: **journal
entries are not subject to the check at all.** The directive this entry
originally carried was doing nothing. It is removed rather than left in
place, because a directive that vouches for nothing is the same failure as a
field every record shares — it looks like a handled finding and is not.
