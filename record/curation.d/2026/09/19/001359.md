`#86`'s trunk detector, run over the whole reading list, produced one live
finding worth acting on and it was not subtle. `LIT-377` had written the gap
into its own Standing section three days earlier:

> This note closes the load-bearing gap in that lineage and **leaves three
> others open.**

Christiano et al. 2017, Stiennon et al. 2020, and FLAN. All three are now
filed, and the reading list renders preference learning → summarization →
general instruction following with FLAN alongside.

## What the detector is actually for

The issue predicted the yield would be trunks — papers several documents
agree about and none can cite. It is, but the mechanism is narrower than the
framing suggests, and this case shows it cleanly: **the record already knew.**
Nobody had to infer the gap from a pattern of citations. A human wrote the
sentence "neither is in this record", filed it, and the record carried on.

So the detector is not really finding agreement. It is finding **requests
that were written where nothing could read them.** `DP-004` says a pass finds
only defects its query is shaped like; the sharper version this session
produces is that a request in prose has no code, resolves to nothing, and
therefore cannot be the subject of any check luria runs. The lint can tell
you a citation points at a retired document. It cannot tell you a paragraph
asked for something.

That is worth more than the three notes. The same shape appears twice more in
the sweep, as stale requests rather than open ones — `LIT-181` still asking
for a practice `SOTA-169` now carries, `LIT-180` still calling Qwen3 unfiled
when `LIT-182` is the Qwen3 technical report. Both went stale silently for
exactly the same reason.

## Why the ratio is the result, not the three papers

348 Standing sections → 174 naming three or more documents → 58 with
agreement language → 3 live. Most of the 58 are trunks **already filed**,
which is what a query run late looks like and is the honest headline.

The two narrowings are not alike. 174 → 58 was mechanical. 58 → 3 required
reading each section against the current record, because `"All three
practices are confirmed"` — an audit result — is indistinguishable at grep
distance from `"the thing all four papers agree on ... is untouched"`, which
is a trunk. Budget the second narrowing; the grep is free and tells you
almost nothing.

## The relation FLAN gets, and why it took a minute

`compared_against`, not `extends`. The temptation is `extends` because FLAN
is chronologically between Stiennon and InstructGPT and is about the same
problem. But `ADR-011` is specific: `compared_against` means somebody ran
the comparison, and InstructGPT is not built on FLAN — it beat it, 73.4 ± 2%
against 29.8 ± 2%, on the OpenAI API's prompt distribution.

Filing it as a rival rather than an ancestor also preserves the thing that
makes it interesting. `NOTE-161` already recorded the assumption underneath
that number: the prompts were what API users actually asked for, while FLAN
optimizes zero-shot generalization to unseen *academic task types*. The
record therefore now holds a decisive comparison **and** the reason it is
narrower than it reads — but only because the losing arm is a document rather
than a name in a table.

## Christiano is not a language paper

Worth saying explicitly in its Standing section, because the pull to read it
as "early RLHF" is strong and wrong. Atari and simulated locomotion, no
language model anywhere in it. What crossed into language was the loop, and
Stiennon is where it crossed. Collapsing that into a continuation would make
the lineage read as one idea getting bigger, when it is one construction
being moved to a domain it was not built for — which is the more useful thing
for a reader to know.
