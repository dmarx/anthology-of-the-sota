# LIT-022: Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism

Shoeybi et al. (2019) — [ARXIV-1909.08053](https://arxiv.org/abs/1909.08053)

## Key takeaways

- **Tensor parallelism as it is now practised.** The partition is chosen so the
  nonlinearity between two GEMMs needs no synchronisation: split the MLP's
  first weight matrix **column-wise** so GeLU applies independently to each
  piece, then the second **row-wise** so it consumes that output directly.
  Same for attention — `Q`/`K`/`V` column-wise, output projection row-wise
- The whole implementation is a conjugate operator pair: `f` is identity
  forward and all-reduce backward, `g` is the reverse. **Two all-reduces
  forward and two backward per transformer layer**, in native PyTorch, with no
  compiler or library changes
- **Fuse the parallel logit GEMM into the cross-entropy loss.** All-gathering
  logits communicates `b×s×v` elements; fusing reduces it to `b×s`
- **8.3B parameters on 512 GPUs at 15.1 PetaFLOPs, 76% scaling efficiency**
  against a 39-TeraFLOP single-GPU baseline. Vocabulary padded 50,257 → 51,200
  so the **per-GPU slice is a multiple of 128**; hidden size per head fixed at
  96 for consistent GEMM shapes
- **More attention heads costs model-parallel efficiency** — 16 → 32 heads at
  8-way parallelism shrinks the per-head GEMMs and grows the softmax. The paper
  warns explicitly that head count is a systems hyperparameter, not only an
  architectural one
