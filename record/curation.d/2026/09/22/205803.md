title: 'Sixty rows, and fifty-seven of them were the same thing'
created: '2026-09-22T20:58:03'
tags: [record, curation]
---

**The issue had already done the hard part.** `#202` found the check, ran it,
classified what a row can mean, and wrote the sequencing down: work the rows,
then declare, and only if the residue is small. It also said why not to just
turn it on — there is no `unbound-ok:`, so a report reading 60 would have no
way back to zero and would become wallpaper. I followed that and it was right.

**What I did not expect was how one-sided the distribution turned out.** The
issue named three readings and ranked the third — the record drew the wrong
practice from the paper — as "the one worth the pass". It found zero
instances. `#201` had already closed the RETRO case that prompted the issue.
What remained was 57 rows of plain under-tagging and one mis-tagged practice.

Some of those are embarrassing in a useful way. *Attention Is All You Need*
was not tagged `attention-techniques`. FlashAttention was not tagged
`systems-optimization`. CheckFreq was not tagged `distributed-optimization`,
whose blurb literally ends with the word "checkpointing". Twelve diffusion
practices did not carry `generative-modeling`. None of this was visible in
prose — every one of those documents *says* what it is about in its body. The
divergence lived entirely in a `tags:` field, which is exactly the class of
defect a structured-field detector exists to find, and exactly the argument
`#203` makes.

**The risk in a pass like this is that clearing the check becomes the goal.**
That is the forbidden move, and it is very easy: 60 rows, each of which goes
away if you add almost any tag the other side has. The discipline I held to
was `CLAUDE.md`'s test — *would someone browsing that topic be right to expect
this document?* — applied per row, one topic each, with a written reason. The
batch is in the decision and can be audited. Where I could not answer the test
honestly, I said so rather than adding the tag quietly: `SOTA-060` sourcing
`LIT-043` is the weakest row in the pass and is named as such.

**That weak row turned out to be a second finding.** `LIT-043`'s entire note
is the sentence "3D parallel training strategy". A note that thin cannot say
what it is about, so of course its tags disagree with a practice drawn from
it. Three of the notes I touched are one-liners like that. The unbound-source
query is, partly, a reading backlog wearing a tagging costume.

**A mechanical guard I am glad I ran.** `primary_topic` derives `{tags[0]}`,
so appending is safe and prepending silently refiles a document. I appended
throughout, then diffed the first tag of all 49 changed files against `HEAD`
to check. Exactly one moved — `SOTA-033`, on purpose. Having the check take
four lines and one minute is the difference between believing that and knowing
it.

**Two invented references, both caught, both the same reflex.** The config
comment I wrote first said "Declared by `ADR-055`", a decision number that does
not exist, and cited `LU-#288` for the missing upstream directive, an issue
number I had no basis for. This is the fourth time today I have written a code
from expectation rather than from evidence, and the fourth time something
caught it — here, only because I stopped to check rather than because a tool
did. That is worse than the times the lint caught it.

The fix carries its own lesson: the config now cites `#202`, an issue number,
and not a decision code at all. `ADR-039` records that concretization rewrites
the record and not `luria.yaml`, so a temporary code written into the config
goes stale with no mechanism to fix it — which is how that file accumulated
fifteen dead citations the last time anybody looked.

**On declaring it.** The residue is zero, so the invariant is on, and
`unbound-lineage.md` now asserts three invariants instead of two. This does
not make the check free: a new practice whose source shares no topic with it
will show up in the report, and the fix will be the same judgement made 60
times here. What it buys is that the judgement happens while the document is
being filed and the context is loaded, rather than two years later in a pass
like this one.
