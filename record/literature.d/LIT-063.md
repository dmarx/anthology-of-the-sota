# LIT-063: TVM: An Automated End-to-End Optimizing Compiler for Deep Learning

Chen et al. (2018) — [ARXIV-1802.04799](https://arxiv.org/abs/1802.04799)

## Key takeaways

- The problem is portability of *performance*, not of code: frameworks lean
  on vendor-specific operator libraries tuned for a narrow range of
  server-class GPUs, so every new target — mobile, embedded, FPGA, ASIC —
  costs a manual re-optimization.
- TVM exposes both levels at once. Graph-level: high-level operator fusion,
  the transformation that turns a chain of small memory-bound ops into one
  kernel and stops the round-trip to memory between them. Operator-level:
  mapping to arbitrary hardware primitives and hiding memory latency.
- The low-level schedule space is too large to hand-tune per target, so it is
  *searched*, guided by a learning-based cost model — which is what makes the
  approach automated rather than a better library.
- Results competitive with hand-tuned vendor libraries across low-power CPU,
  mobile GPU and server GPU, plus an FPGA accelerator back-end. Open source
  and in production at several companies.
