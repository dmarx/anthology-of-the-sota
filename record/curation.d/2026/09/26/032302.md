Swin was the last unfiled Tier A/B item on `#342` and it had been last for a
reason that was stated three separate times and was correct every time: nine
documents mention it, all nine use it as somebody else's experimental backbone,
and no practice depends on anything it says. `#326` put it low. `#290` promoted
it and nobody worked it. The `#342` comment left it there on the record that
its file count was partly `grep swin` matching **"swings"**.

All of that survives the reading. **What the ranking could not see is that the
paper's value to this record is in its ablation table, and a dependence count
cannot see an ablation table.**

## The finding

Swin runs every design ablation on three benchmarks — ImageNet-1K
classification, COCO detection, ADE20K segmentation — with one architecture and
one recipe. Table 4:

| variant | ImageNet top-1 | COCO AP_box | ADE20K mIoU |
|---|---|---|---|
| no position encoding | 80.1 | 49.2 | 43.8 |
| absolute only | 80.5 | 49.0 | 43.2 |
| absolute + relative | 81.3 | 50.2 | 44.0 |
| **relative only** | **81.3** | **50.5** | **46.1** |

The absolute position embedding is worth **+0.4** top-1 and **−0.2** box AP and
**−0.6** mIoU. **A design choice that a classification benchmark scores with
the wrong sign.**

That is the whole finding, and the restraint it needs is worth stating: the
three metrics are not commensurable. A point of top-1, a point of box AP and a
point of mIoU are different quantities, so "the effect is 2–3× larger on dense
tasks" — which the shifted-window row invites, 1.1 top-1 against 2.8 box AP and
2.8 mIoU — is not a claim this table supports. **The direction is the only part
that needs no common scale**, and it is the part the practice rests on.

## Where it lands, and the coincidence that makes it sharp

`SOTA-388` is this record's plain-ViT baseline recipe. Five changes, in
descending order of what the ablation attributes to each; the smallest of the
five is **fixed 2D sin-cos position embeddings, worth 0.4 points**.

That is the same 0.4 points, on the same benchmark, for the same kind of
encoding, that Swin measures as negative on both dense tasks. Different
architecture and a different encoding, so it refutes nothing — but it marks
which row of a five-row recipe is the one to re-measure before using the
baseline as a backbone. v2 says so; the recommendation is unchanged, because
`SOTA-388` is explicitly a classification baseline and says so in its own
"When this applies".

`SOTA-358` is the larger one. It states the inductive-bias trade on **one
axis** — prior against data volume — and its Conditions are four statements
about data scale. The downstream task is held fixed at classification
throughout and never named as a variable. Swin varies it inside one model, and
the invariance prior's value changes sign. v3 adds that Condition and spends
most of its words on what it does *not* show, because the tempting reading is
the wrong one:

- not a data-scale sweep, so the threshold does not move;
- a position encoding, not convolution, so it is one narrow expression of
  translation invariance;
- and **not Swin-beating-ViT**, which varies attention pattern, resolution
  schedule, position encoding and recipe at once, and whose dense-task DeiT
  baseline is a retrofit built with deconvolution layers.

**Generalising:** a practice can name its scope honestly on every axis it
thought of. `SOTA-358` says the numbers do not transfer, says the threshold is
architecture-specific, says it assumes you choose the data scale. It never says
which task it was scored on, because the task was not a variable in the
experiment that produced it. **An unnamed constant is invisible in exactly the
way a named limitation is not**, and the only thing that finds one is another
paper that varied it.

## Two things read carefully rather than quickly

**The paper's own strongest claim is not supported by its headline.** Its
conclusion is that "inductive bias that encourages certain translation
invariance is still preferable for general-purpose visual modeling,
particularly for the dense prediction tasks". The evidence for that is Table
4's position rows, inside one architecture. The COCO and ADE20K wins over DeiT
and ViT are not evidence for it. The citable half is the benchmark table and
the load-bearing half is the ablation, which is the same shape the CFG unit
found in `2207.12598` four days ago.

**Shifted windows are a speed result.** Table 4's `w/o shifting` row shows
cross-window connection matters (+1.1 / +2.8 / +2.8). Table 6 shows that
*sliding* windows get the same accuracy to within noise — 81.4/50.2/45.8
against 81.3/50.5/46.1 — and Table 5 shows shifted windows are 4.1×/1.5×
faster, because every query in a window shares one key set. Those are two
different claims and the paper's title encourages conflating them.

## No theory, deliberately

The paper attributes the sign flip to translation invariance mattering more for
dense prediction, in one sentence, with nothing isolating it — no arm varies
equivariance while holding the encoding fixed, or the reverse. So the account
and the measurement are one observation told twice. The standard applied to
autoguidance three days ago holds here in the other direction: a mechanism
claim earns its status when the experiment includes an arm the mechanism says
must fail, and this one has none. The flip is measured and unexplained, and the
note says that rather than dressing the correlation as a reason.

## What the ranking was actually wrong about

Not the count. The count was right nine times over — nine documents, every one
of them using Swin as a test subject. The ranking question was **"what depends
on this?"**, and the answer really was "nothing depends on what it says".

`#326` had already replaced that question with **"what does this paper measure
about something the record relies on?"** and this unit is the first where the
two questions give different answers for the same paper. Swin measures
something about `SOTA-388` and `SOTA-358` that neither of them can measure
about itself, while depending on neither. **A paper can be worth filing purely
as an instrument, and nothing in a dependence count will ever say so** — you
have to have read the ablation.

Which is also the honest limit of the corrected question: it is still asked
from outside the paper, off a title and an abstract, and this table is in
neither.

## Deliberately not in this unit

`SOTA-320` and `THEORY-062` rest on "ViT, Swin and GPT all train without
warmup". That sweep is strong precisely because Swin is architecturally far
from ViT — different attention pattern, resolution schedule and position
encoding — and neither document says so. It is a weakness in how the
generality is argued, not an error, and the note now gives a reader the
referent to check it against. Left alone.

Tier A/B of `#342` is now complete. Tier C remains, to be declined again with
better reasons.
