Unit F of `#304`. SigLIP, which the audit ranked twentieth and which turned
out to carry the cluster's sharpest methodological finding.

## The shape of the finding

"Contrastive learning wants the biggest batch you can afford" was settled
folklore. SigLIP trained from 512 to **one million** and found performance
**saturating at about 32k** — and saturating for the **softmax** loss too, so
it is not a fact about their new loss.

The explanation for why this went unnoticed is one sentence in the paper:
existing studies "stop at 64k".

**The ceiling sat just below the point where everyone stopped looking.**

That is worth stating as a general hazard rather than as a fact about batch
size. A consensus formed entirely inside a range is a claim about the range,
and the reason nobody tests outside it is the same reason the range exists —
the cost. Every study was run where the belief holds; none was run where it
breaks; and the belief was reported as though it had been tested.

The record has a name-shaped gap here. `DP-005` covers adoption not being
evidence, `DP-009` covers counting as the antidote, `DP-010` covers the
citable sentence being the least supported. This is a fourth: **the untested
extrapolation past a convention**. Not filed as a principle in this unit,
because one instance is not grounds for a `DP`, but recorded so the second
instance has something to attach to.

## Three arguments that could all have been wrong together

With this unit the record holds three reasons the negative count is not a
quality dial, and the useful property is that **none is downstream of the
others**:

- `THEORY-085` — the InfoNCE bound cannot certify more than `log N`.
  Information-theoretic, derived from the objective's own algebra.
- `LIT-591` (SimCLR) — batch-size gaps "decrease or disappear" with longer
  training. A training-budget argument, measured on one method.
- `SOTA-tmptiobf` (this) — the curve flattens at 32k, measured to 1M.
  Direct, empirical, on a different objective family.

Different methods, different labs, different kinds of argument. They could
have disagreed and they did not. **That is what corroboration looks like when
the record gets it, and it is rare enough to say out loud** — most of `#304`'s
findings rest on one measurement from one group.

It also means the three should not be collapsed into one document. Each would
survive the other two being wrong.

## The line that keeps getting dropped

Fourth paper in this cluster with exactly one initialisation detail that is
load-bearing and easy to omit:

- CLIP: the temperature is **clipped** at logit scale 100, "necessary to
  prevent training instability".
- SwAV: the entropy regularisation `ε` must be **kept low**, or everything
  collapses.
- BYOL: removing **weight decay** makes BYOL and SimCLR diverge.
- SigLIP: a **learnable bias** initialised at `−10`, because at
  initialisation `|B|²−|B|` negatives against `|B|` positives means the
  imbalance "dominates the loss".

None of these is the paper's contribution and each is a sentence. The pattern
is consistent enough to be a reading instruction: **in a contrastive paper,
find the initialisation paragraph before reading the results.** Every
document in this unit now carries its own such line explicitly, because that
is the part a reimplementation loses and the part a note can preserve.

## An unbound line, answered the way [ADR-049](../../record/decisions.d/ADR-049.md) asks

Declaring `extends: SOTA-359` on the sigmoid practice put it in a chain with
`SOTA-360` and `SOTA-363`, and the lint reported the **line** unbound — every
individual edge bound, the whole sequence sharing nothing, which is the
weaker signal `ADR-049` says to read whole before acting on.

Reading it whole: the other three all carry `training-optimization` and the
new one did not. The fix is not to drop the relation, because the relation is
true — SigLIP keeps CLIP's supervision and changes only the normalization.
The fix is that `training-optimization` is **true of the new document and was
missing**: its central claims are about batch size (better below 16k, which
batch sizes are reachable at all) and about an initialisation detail that
keeps early training stable. Someone browsing that topic would be right to
expect it.

Third time this session the answer to an unbound relation has been a topic
that was genuinely absent rather than a label invented to satisfy the check.
Worth noting the pattern holds: **a new document joining an established chain
is the common case, and the missing tag is usually the one the chain is
already about.**

## A code reference that was wrong for three minutes

Worth recording because the habit is what caught it. Writing the SigLIP note
I reached for "[LIT-590](../../record/literature.d/LIT-590.md) (SimCLR)" from memory of unit B's filing order.
`LIT-590` is MoCo; SimCLR is `LIT-591`. Checked before committing, because
the same session had already published a wrong document reference on `#304`
— attributing `SOTA-337`'s recommendation to `SOTA-338` — and that one
reached an issue comment before anyone noticed.

Two instances now of the same failure: **a code recalled rather than looked
up.** The first cost a public correction; the second cost nothing because the
first had happened. Cheap lesson, worth keeping cheap.
