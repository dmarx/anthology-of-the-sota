`#84` asked for one pass: run the inverse of every declared relation, so the
record can make the only kind of clean statement `DP-004` permits anyone to
trust — *every declared relation has been checked in both directions.* It can
now make that statement. The script is below so the next person runs it
rather than reinventing it.

## The result

| query | findings |
|---|---|
| `extends` / `extended_by` — parent does not claim the child back, or names a document that does not exist | **0** |
| `compared_against` — declared from one end only, or names nothing | **0** |
| `corrects` / `corrected_by` — one end only, or names nothing | **0** |
| `explains` / `explained_by` — one end only, or names nothing | **0** |
| `NOTE.paper` — a reading of nothing, or two readings of one paper | **0** |
| `contested_by` set while `consensus` is not `contested` | **0** |
| `consensus: contested` naming nobody | **0** |
| `corrects` where the corrected document is still `Active` | 14 — *see below* |
| `introduced_by` not among `source:` | 4 — *see below* |
| `compared_against` with no trace in either body | 14 — *see below* |

Every symmetry query is zero, and that is not luck: `luria link --fix`
derives each converse from whichever end declares it, so the class is
structurally satisfied and stays that way. Worth knowing that the guarantee is
the tool's rather than the contributors' — it means these seven queries are
**not worth re-running** unless the fixer changes.

## Three queries whose premise was wrong, not whose subject was

This is the useful half, and it is `DP-004` turned on itself. The corollary
says a pass finds only defects its query is shaped like. The dual: **a query
run in the other direction can be mis-shaped in that direction too**, and
then it reports the record as broken when the record is right.

**`corrects` → the corrected document should be retired.** The `corrects`
blurb says the earlier document is "normally `Superseded`". Fourteen are not.
All fourteen carry a frontmatter comment naming **`Corrective succession
(ADR-017)`** and saying exactly why: QK-Clip fixes a failure mode of Muon at
a trillion parameters and you cannot QK-Clip without using Muon; RoPE
rescaling is the step a RoPE model takes when it needs a longer window;
`SOTA-146` fixes GRPO's published objective and needs GRPO's group baseline
to fix. The corrected practice is not wrong — it is right in its own regime,
and the corrector is conditional on it. The record had annotated every
instance before the query existed.

**`introduced_by` should be among `source:`.** Four are not. That is the
field working: `ADR-029`, refined by `ADR-030`, exists precisely to separate
*who first said it* from *what evidenced it*, and the blurb says so — "the
work that first made this recommendation, which is frequently not the work
that evidenced it". `SOTA-240` is introduced by the 2012 dropout paper and
sourced to the two papers that measured it. A query asserting containment
asserts the opposite of the decision.

**`compared_against` should leave a trace in the body.** Fourteen pairs do
not, and most are false positives: `LIT-230`, `LIT-233` and `LIT-235` mention
DeepSeekMath or GRPO eight to twelve times each. They narrate the comparison
**by paper name**, not by code. The query was shaped for codes. Any query
over prose that looks for `LIT-\d+` is asking whether a document was *linked*,
not whether it was *discussed*.

## What the third query did find, and why I did not fix it

Strip the false positives and three groups remain, all the same shape: a
`compared_against` edge between practices drawn from **one paper**.

- `SOTA-040` ↔ `SOTA-041`, both sourced to `LIT-028` (Kaplan)
- `SOTA-061` ↔ `SOTA-062`, both sourced to `LIT-061`
- `SOTA-010` / `SOTA-011` / `SOTA-012`, all three sourced to `LIT-014`

`ADR-011` is unambiguous: `compared_against` means somebody ran the
comparison, and a shared topic is not one. Kaplan et al. did not measure
"larger models are more sample efficient" against "lr tuning less important
for larger models" — those are two findings, not two arms.

The third group says so itself. `SOTA-011` and `SOTA-012` carry:

> The link stays: it records that three readings of one figure were filed
> together.

That is a **sibling** relation, honestly described, wearing the only field
available. And the information is already carried: all three name `LIT-014`
as `source:`, so "filed together from one paper" is derivable without any
edge at all.

I have not removed them. Two reasons. The `SOTA-010` group is a documented
decision and reversing it silently is not mine to do. And the question
underneath is a vocabulary question — whether the record wants a sibling
relation, or whether shared `source:` is enough and these edges should go —
which is an `ADR`, not a sweep. `ADR-047` is the precedent: two passes asked
for a `specializes:` relation and the answer was that `extends` already
covered it, found by writing the blurb. The same discipline applies here, and
the blurb to write is `compared_against`'s own, which already exists and
already says these edges are wrong.

## The script

Kept because `#84`'s whole argument is that a query living in a devlog entry
gets reinvented rather than run. It is ~80 lines of `yaml.safe_load` over
`record/**/*.md`, building `code -> frontmatter` and checking each relation
against its declared converse. Every check is three lines. Re-run it after
any change to `luria.yaml`'s `references:` tables, which is the only event
that can make the symmetry guarantee stale.
