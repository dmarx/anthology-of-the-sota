**The owner overruled a decline ([#241](https://github.com/dmarx/anthology-of-the-sota/issues/241)).** This record opened [#241](https://github.com/dmarx/anthology-of-the-sota/issues/241) rather than
filing a practice, on the CLAUDE.md rule that a recommendation needs a paper
that produced evidence about the claim. Genesys is an instance of the failure,
not a measurement of it. The instruction back was to file it anyway and leave
`introduced_by:` null — *we at least know the practice exists even if we
don't have a great source for it* — and that is the right call for a reason
worth writing down: the alternative leaves the shelf empty, which is quieter
but not more honest.

**"Leave it null" turned out to cost a decision.** The expectation was a
one-line edit. `luria lint` rejects `introduced_by: []` and
`introduced_by: null` identically, with the message *no `introduced_by:` in
frontmatter* — both are read as absent, and `required: true` is what
`ADR-030` set. So honouring the instruction meant amending `ADR-030`, which
is `ADR-tmpvlp2h`, rather than editing a field.

**`ADR-030`'s argument survives intact, which is why the amendment is narrow.**
It required the field because an absent one was ambiguous between "the origin
is the primary source" and "nobody checked". Both readings are still bad. The
third case — the record looked and can name no document — is one neither
covers, and it is a positive finding rather than a gap. The schema goes to
`required: false`; the convention is stricter than the schema (write the
field empty, comment beside it, explain in the body), and it is a convention,
which is the honest weakness.

**What would fix it properly is upstream and out of reach.** A `required:`
satisfied by an explicitly empty list but not by an absent key would give both
the guarantee and the expressiveness. luria collapses the distinction today.
Named in the ADR; not filable from this repository.

**The global `sed` trap fired again, and was caught by `git diff`.**
Replacing a hand-guessed `ADR-050` with the temp code across `luria.yaml`
also rewrote three pre-existing `ADR-050` citations that had nothing to do
with this work — `ADR-050` is a real decision about two topic vocabulary
additions. Reverted the file and re-applied the single intended hunk with an
anchored replacement. Same lesson as the `formerly:` clobber earlier today:
a global substitution across the record does not know which occurrences are
yours.

**And the number was guessed, which is the deeper error.** Writing `ADR-050`
at all — before running `luria new adr` — assumed the next free number. There
were already fifty-two decisions. Temp codes exist precisely so that nothing
has to guess, and `luria.yaml` is in `code.globs`, so concretization reaches
the citation there too.
