`#163` is a fifteen-item checklist. Measured against the record with `#137`'s
criterion — *something here has to be answerable from it* — one item is
load-bearing and the rest have no dependents.

## NeRF

`SOTA-205` recommends replacing **"a large coordinate network"** with a
compact explicit structure and a small decoder. All four of its sources are
responses to the same paper: Instant-NGP, K-Planes, 3D Gaussian Splatting,
NeuS2. Two of them name it in their own notes.

So the record held a recommendation against a design it could not point at.
A reader following `SOTA-205` met a description where a citation should be.

Filed with **no practice**, which is the same determination `LIT-428` carries:
the record's position on this design is already `SOTA-205`'s, and filing a
competing practice would be recommending both. The trunk is here to make the
existing recommendation legible, not to compete with it.

The reading is worth having for one thing the summary would have missed.
**Positional encoding is not a refinement in this paper** — the authors state
the basic implementation "does not converge to a sufficiently high-resolution
representation", and the no-encoding ablation is oversmoothed. That is the
part which travels outside vision: it is a claim about what a
coordinate-input MLP can represent at all, which is why the note carries
`representation-and-encoding` as its second tag.

## The rest of the list, measured

| item | documents mentioning it |
|---|--:|
| NeRF | **4** |
| interpolant / SiT | 3 |
| Tensor Programs | 2 |
| Fourier features | 1 |
| SIREN, StyleGAN, CycleGAN, Projected GAN, cold diffusion, diffusion forcing, SAE / logit lens, ReFT, structured-output sampling | **0** |

`#137` ended in exactly this shape and it is worth naming as a pattern rather
than rediscovering it a third time: **a checklist assembled from memory ranks
by salience, and salience is uncorrelated with what a record can answer.**
Nine of these fifteen have no dependents at all. That is not an argument
against filing them eventually; it is an argument that the list is not
ordered, and that ordering it costs one grep.

**One item was already done and the issue did not know.** It asks to "at very
least add TP-IV for muP". `LIT-148` is Tensor Programs **V**, which *is* the
µP paper, and `SOTA-143` already parameterizes with µP from it. TP-IV is the
feature-learning theory underneath — a `THEORY` candidate, not a missing
practice, and a different request from the one the checklist makes.

That is the third time this session a tracker item has been stale in a way
only measurement revealed. The others: `LIT-180` calling Qwen3 unfiled when
`LIT-182` is the Qwen3 report, and `LIT-181` asking for a practice `SOTA-169`
already carried. All three are the same defect — **a claim about the
record's contents, written where nothing can check it.**
