`1805.07039` was the cluster's one remaining mechanism gap, named by identifier in
five held documents and by the previous unit as the only paper that would let the
record say *why* half of `SOTA-430`'s verdict table fails. It does, and the answer
is stronger than the gap sentences implied.

## Theorem 1, which is not the shape I expected

> In a random three-layer CNN, if the number of filters `N` is sufficiently
> large, GBP at the `k`-th logit can be approximated as `s_k^GBP(x) ≈ x`

Not "resembles the object". Not "highlights the object". **Recovers the image**,
in a network whose weights are i.i.d. Gaussian, for any logit `k`. Theorem 2 puts
the saliency map and DeconvNet in the same network at `N(0, I)`: noise. So neither
the plain gradient nor the backward ReLU alone produces a recognisable map, and
the combination guided backprop uses does.

And the paper draws the consequence for the rival account in one line: "according
to the linear model explanation, backpropagation-based methods are visualizing
learned weights, which should be random noise as they are all sampled from i.i.d
Gaussians. Obviously, it is inconsistent with the actual behavior of GBP."

The second cause is architectural and quantified: filters needed scale as
`Õ(p/ε²)` in filter size, so a 3×3×3 filter needs at most `O(10³)` for error
under 0.1. **Local connectivity is not a vague contributor; it is a small `p`.**

## The arm that runs the other way

Every test in this cluster so far holds the input and destroys the weights. This
paper adds the mirror: FGSM turns "panda" into "busby" on VGG-16, so the input
barely moves and the predicted class flips. A class-sensitive map must change; a
recovery map must not. The saliency map "changes significantly"; GBP and DeconvNet
"remain almost unchanged".

Two more arms are architectural surgery. Delete local connections and GBP fails
too — at `N_h = 70000` hidden units, which the paper itself calls "definitely
unrealistic", an FCN still does not match a CNN with `N = 64`. Add max-pooling to
the random CNN and **only DeconvNet moves**, noise to interpretable, while GBP and
saliency are untouched. Four arms, and the account is filed `Active`.

## What it does to a sentence I wrote yesterday

`LIT-727` quotes Springenberg's explanation that "the bottom-up signal in form of
the pattern of bottom ReLU activations substitutes the switches", and **declined**
to conclude that the map's structure therefore comes from the input rather than
the weights. The stated reason: bottom ReLU activations are themselves computed by
the network, so randomizing the weights changes them.

Theorem 1 removes that objection by making the network random. GBP recovers the
image with Gaussian weights.

So the conclusion I declined to draw is true. **And the restraint was still
right**, which is the part worth separating: Springenberg's sentence does not
prove it, and the proof took a different route — a theorem about what a backward
ReLU does to a random convolutional map, not an argument about what the switches
were doing. v3 says both halves, because a note that records "I stopped short"
and is later vindicated reads as timid unless it also records *why* stopping short
was correct.

Three units in a row have now turned on this distinction. [#384](https://github.com/dmarx/anthology-of-the-sota/issues/384) declined an
inference and Sixt refuted the published version of it. [#386](https://github.com/dmarx/anthology-of-the-sota/issues/386) corrected a claim I
*had* asserted from a citation. This one confirms a claim I declined to assert.
**The difference between the three is not caution, it is whether the argument in
front of me supported the sentence I wanted to write.**

## The mechanism was already in the record as a rhetorical comparison

`LIT-713`'s negative half is that "an untrained edge detector produces maps
'strikingly similar' to several methods'", and `SOTA-430` carries it as the
argument for not validating a map by eye. Nie et al.'s trained-network passage:
the weights "control which image patch could form an active path to the class
logit. More importantly, this filtering process is not class sensitive (e.g. the
edge detector)."

**Partial image recovery is what an edge detector approximates.** A comparison
used in 2018 to embarrass the methods turns out to be the mechanism, and the
record held the comparison for a day without the account.

## The defect in how I wrote yesterday's unit

Yesterday's unit put a three-row partition table into `SOTA-430`, `LIT-729`,
`THEORY-113` and `THEORY-114`, so the boundary between accounts would be legible
from every document in the cluster. It was legible. It was also **four copies of a
gap sentence**, each reading "not held — `1805.07039`", and all four went stale
one unit later.

This journal has recorded that gap sentences have roughly a one-unit half-life —
three times, on single sentences. This is the same defect at scale, and the thing
that makes it worse is that it looked like good practice: repeating the boundary
is how you stop a reader inferring the wrong scope from whichever document they
landed on.

**The narrow lesson.** A cross-reference that names a held document is maintained
by the toolchain: rename it and `luria concretize` rewrites every copy; retire it
and the lint flags every citation. A cell reading *"not held"* is maintained by
nobody, because it is a claim about the **absence** of a relation and `luria lint`
checks relations that exist. So duplicating a positive cross-reference costs
nothing and duplicating a negative one costs one edit per copy per unit.

Whether that argues for one canonical table with the others pointing at it, or for
a lint rule that reads bare arXiv ids near words like "unheld", is a decision this
entry does not make. It is at least the fourth instance of the same underlying
shape and probably wants an ADR rather than another journal paragraph.

## Residue

Four `#290` reversals remain — Grad-CAM, InputXGradient, plain-gradient saliency,
SmoothGrad — and they are still referent gaps rather than measurement gaps, since
every verdict about them is stated correctly from `LIT-713`. `1706.03825`
(SmoothGrad) is the strongest of the four and has risen again: it is now named by
`LIT-725`'s Theorem 4.1 as the kernel-smoothing meta-algorithm, by `LIT-729` as a
non-converging gradient method, and here as one of the two methods unaffected by
adding max-pooling.

`SOTA-430` is at v6 and the one thing it still leans on that it should not is the
visual claim in its headline example, whose figure both Adebayo and Sixt amended.
The fix is to state the verdict from the SSIM curves. It is deliberately not in
this unit either, and it is now the practice's own oldest outstanding defect
rather than a consequence of anything arriving.
